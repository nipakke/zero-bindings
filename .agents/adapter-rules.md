# Adapter rules

- Core owns Zero behavior. Adapters consume `ZeroSession` resources and `ObservableView` snapshots; never reimplement `Output`, materialization, batching, completion, relationship handling, `applyChange`, or `skipYields`.
- Adapters own host source conversion and teardown. `Source.subscribe()` is passive: a host explicitly starts query resources and disposes resources/session through its lifecycle. Adapters never close or otherwise clean up Zero clients.
- `src/core/` and `src/index.ts` stay framework-free. Each shipped adapter has its own subpath and optional peer dependency. There is no generic `Adapter`/`createAdapter()` abstraction; the plain mirror in `tests/core/host-neutrality.test.ts` pins the same boundary.
- Vue bindings are inert at `create()`. The caller supplies one client value/ref/getter and optional mutation defaults; `install(app)` creates and provides one core session, returns it, and disposes it from `app.onUnmount`. Installing one instance on multiple apps creates independent sessions over the same source; use another instance for another client.
- Svelte bindings are inert at `create()`. `ZeroProvider` calls `provide()` during component initialization because `setContext()` is init-only, and its `$effect` destructor disposes the session. Hooks use that instance's `getContext()` key and throw outside the provider. SSR effects do not run, so SSR starts no resources and registers no disposal.
- Both adapters convert framework reactivity to pull/subscribe sources and mirror whole snapshots into host state. Vue uses scope disposal; Svelte uses the mirror effect lifecycle. Neither reimplements the core observable/view contract.
- `src/adapters/nuxt/**` is the sole cross-adapter exception: `NuxtBindings` composes Vue and owns the package's only SSR path. It is experimental and undocumented; install is client-only, server `useSession()` throws, server `useMutation()` is inert and throws on `mutate()`, and payload rows yield to live query `complete`/`error`.
